NestJS Fundamentals Project Explanation
شرح مشروع NestJS Fundamentals

1. الفكرة العامة للمشروع

هذا المشروع عبارة عن تطبيق NestJS بسيط جدًا لتعلّم أساسيات بناء REST API. الهدف الأساسي منه هو إدارة بيانات المستخدمين Users من خلال مجموعة endpoints مثل: Create, Get All, Get One, Update, Delete.

المشروع لا يستخدم قاعدة بيانات حاليًا. بدلًا من ذلك، يتم حفظ البيانات داخل مصفوفة في الذاكرة اسمها users داخل UserController. هذا يعني أن أي بيانات يتم إضافتها ستضيع بمجرد إعادة تشغيل السيرفر.

1. Project Overview

This is a very small NestJS project built to learn the basics of a REST API. Its main purpose is handling user data through endpoints such as Create, Get All, Get One, Update, and Delete.

The project does not use a database yet. Instead, data is stored in an in-memory array called users inside UserController. That means all data is lost whenever the server restarts.

3. كيف يبدأ التطبيق؟

في main.ts يتم إنشاء تطبيق Nest باستخدام NestFactory.create(AppModule) ثم الاستماع على البورت 3000 أو قيمة PORT من البيئة.
في app.module.ts يتم استيراد UserModule. هذا يعني أن كل routes الموجودة في جزء المستخدمين أصبحت جزءًا من التطبيق.
في user.module.ts يتم تسجيل UserController. وبالتالي Nest يعرف أن requests الخاصة بـ /users ستذهب لهذا الـ controller.

3. How the App Starts

In main.ts, Nest creates the application with NestFactory.create(AppModule) and starts listening on port 3000 or process.env.PORT.
In app.module.ts, the root module imports UserModule, which makes user routes available in the app.
In user.module.ts, UserController is registered, so Nest knows where to send requests that target /users.

4. أصل الـ Route داخل UserController

السطر @Controller('users') يعني أن هذا الـ controller مسؤول عن كل المسارات التي تبدأ بـ /users.

أمثلة:

  • @Get() يصبح GET /users
  • @Get(':id') يصبح GET /users/:id
  • @Post() يصبح POST /users
  • @Delete(':id') يصبح DELETE /users/:id

4. Route Base in UserController

The line @Controller('users') means this controller handles every route that starts with /users.

  • @Get() becomes GET /users
  • @Get(':id') becomes GET /users/:id
  • @Post() becomes POST /users
  • @Delete(':id') becomes DELETE /users/:id

5. شرح الـ Entity والـ DTOs

5.1 UserEntity

ملف user.entity.ts يحدد شكل المستخدم داخل النظام: id, username, email, country.

5.2 CreateUserDto

هذا الملف يحدد البيانات المطلوبة لإنشاء مستخدم جديد. عند عمل POST /users يجب إرسال: username, email, country.

5.3 UpdateUserDto

هذا الـ DTO يستخدم PartialType(CreateUserDto)، وده معناه أن نفس الحقول الموجودة في CreateUserDto تصبح اختيارية في التحديث.

5. Entity and DTOs

5.1 UserEntity

user.entity.ts defines the internal user shape: id, username, email, country.

5.2 CreateUserDto

This file defines the required data to create a user. A POST /users request should send: username, email, and country.

5.3 UpdateUserDto

This DTO extends PartialType(CreateUserDto), meaning the same fields from CreateUserDto are reused but become optional for updates.

6. شرح العمليات الأساسية

6.1 Get All Users

Route: GET /users

الميثود find() ترجع المصفوفة this.users كما هي. إذا لم يتم إنشاء أي مستخدمين فسترجع مصفوفة فارغة.

الفكرة: قراءة كل المستخدمين الموجودين حاليًا في الذاكرة.

6.2 Get One User

Route: GET /users/:id

الميثود findOne(id) تبحث داخل المصفوفة عن مستخدم يحمل نفس الـ id باستخدام find().

إذا وجد المستخدم فسيتم إرجاعه. وإذا لم يوجد فستكون النتيجة undefined.

6.3 Create User

Route: POST /users

الميثود create() تستقبل body من النوع CreateUserDto، ثم تنشئ كائن مستخدم جديد وتضيف له id بواسطة uuid().

بعد ذلك يتم تنفيذ this.users.push(newUser) لحفظ المستخدم في المصفوفة، ثم يتم إرجاع المستخدم الجديد.

6.4 Delete User

Route: DELETE /users/:id

الميثود remove(id) تستخدم filter() للاحتفاظ بكل المستخدمين ما عدا المستخدم الذي يحمل نفس الـ id.

تمت إضافة @HttpCode(HttpStatus.NO_CONTENT) لذلك الاستجابة تكون بحالة 204 بدون body.

6. Main Operations

6.1 Get All Users

Route: GET /users

The find() method returns the this.users array as-is. If no users have been created, it returns an empty array.

Idea: read all currently stored users from memory.

6.2 Get One User

Route: GET /users/:id

The findOne(id) method searches the array using find() for a matching user id.

If a user is found, it is returned. Otherwise, the method returns undefined.

6.3 Create User

Route: POST /users

The create() method receives a body of type CreateUserDto, then builds a new user object and adds an id using uuid().

After that, it stores the user with this.users.push(newUser) and returns the newly created user.

6.4 Delete User

Route: DELETE /users/:id

The remove(id) method uses filter() to keep all users except the one whose id matches the route parameter.

Because of @HttpCode(HttpStatus.NO_CONTENT), the response status is 204 with no response body.

7. الـ Logic الداخلي للمشروع

  • المشروع يعتمد على Controller واحد فقط لتنفيذ المنطق.
  • لا يوجد Service layer حاليًا، لذلك كل business logic موجود داخل UserController.
  • لا يوجد Database أو Repository.
  • توليد الـ id يتم باستخدام مكتبة uuid.
  • مصدر البيانات الوحيد هو المصفوفة private users: UserEntity[] = [].
هذه البنية مناسبة للتعلم والبداية، لكنها ليست الأفضل لمشروع حقيقي لأن الـ controller أصبح مسؤولًا عن أكثر من مهمة: استقبال الطلبات، وتنفيذ المنطق، وإدارة البيانات.

7. Internal Logic

  • The project currently depends on a single controller for most behavior.
  • There is no service layer yet, so business logic lives inside UserController.
  • There is no database and no repository layer.
  • User IDs are generated with the uuid package.
  • The only data source is private users: UserEntity[] = [].
This structure is fine for learning, but it is not ideal for a real project because the controller is handling request routing, logic, and data management together.

8. ملاحظات مهمة على الكود الحالي

  • لا يوجد Validation للـ body مثل التأكد من صحة البريد الإلكتروني أو وجود الحقول.
  • إذا تم طلب مستخدم غير موجود في GET /users/:id فالنتيجة ستكون undefined بدل 404.
  • في PATCH إذا كان الـ id غير موجود قد يحدث سلوك غير آمن لأن الكود لا يتحقق من findIndex().
  • في DELETE لا يوجد تأكيد إن كان المستخدم موجودًا قبل الحذف.
  • البيانات تضيع بعد إعادة تشغيل التطبيق لأنها محفوظة في الذاكرة فقط.

8. Important Notes About the Current Code

  • There is no request validation yet, such as checking email format or required fields.
  • If a user is missing in GET /users/:id, the method returns undefined instead of a 404.
  • In PATCH, if the ID does not exist, the current findIndex() flow is unsafe because it is not checked.
  • In DELETE, there is no confirmation that the user existed before deletion.
  • All data disappears after a server restart because it is stored only in memory.

10. الخلاصة

هذا المشروع ممتاز كبداية لفهم NestJS لأنك ترى بوضوح كيف يبدأ التطبيق، وكيف يتم تسجيل الـ module، وكيف يربط الـ controller بين الـ routes والمنطق. الجزء الأهم هنا هو أن كل شيء بسيط ومباشر، لذلك هو مناسب للتعلم قبل الانتقال إلى Service, Validation, وDatabase.

10. Summary

This project is a good starting point for learning NestJS because it clearly shows how the app starts, how modules are registered, and how a controller connects routes to logic. Its simplicity makes it useful for learning before moving to Service, Validation, and Database layers.
